# 实施计划与验收标准

## 1. 实施原则

- 先打通一条可靠闭环，再扩展业务模块。
- 每个里程碑必须有可执行测试和验收结果。
- 接口契约、数据库迁移和部署脚本都属于产品，不是临时附件。
- 模拟数据用于验证，但不能成为生产环境自动回退路径。

## 2. M0：工程基线

### 工作内容

- 建立独立 `HTHIUM.Mes.sln` 和分层项目。
- 配置 .NET 10、Nullable、分析器和统一构建属性。
- 建立配置分环境、机密配置规则和启动检查。
- 统一异常中间件、Problem Details、TraceId和结构化日志。
- OpenAPI、live/ready健康检查。
- 单元测试和集成测试工程。
- Windows Service运行能力。

### 验收标准

- Debug/Release均可一条命令构建。
- 健康检查能区分进程存活和数据库就绪。
- 未处理异常不会暴露堆栈和敏感配置。
- OpenAPI文档可构建生成。
- Windows Service停止时能优雅结束在途请求。

## 3. M1：设备接入闭环

### 工作内容

- 建立MySQL数据库和迁移脚本。
- 工厂、产线、设备、设备凭据。
- 心跳接口、设备最新状态和心跳历史。
- 通用消息信封、原始消息、幂等和顺序检查。
- HTHIUM本地Outbox和后台上传服务。
- 兼容当前接入原型接口的迁移适配；Central WPF不进入正式交付。

### 验收场景

1. 同一消息连续发送10次，只产生一条业务记录。
2. MES断开10分钟后恢复，HTHIUM自动补传且不阻塞PLC线程。
3. 收到序号1、2、5时能识别3～4缺失。
4. 凭据错误、设备禁用和请求超限返回正确状态码。
5. MES数据库不可用时不返回假成功。
6. HTHIUM重启后待发送数据仍然存在。

## 4. M2：报警、生产、质量和快照

### 工作内容

- 报警触发、恢复、确认、闭环。
- 生产记录、工单/批次基础关联。
- 质量结果、不良原因和判定。
- PLC快照元数据、参数定义副本和帧数据。
- 分页查询、筛选、统计和异步CSV导出。
- 坏消息死信、人工重试和归档任务。

### 验收场景

- 报警触发与恢复可稳定关联。
- 历史快照配置改变后仍按原参数顺序回放。
- 大快照超过限制时被明确拒绝，不影响心跳接口。
- 查询百万级测试数据仍使用索引且分页稳定。
- CSV导出不占用普通HTTP请求直至超时。

## 5. M3：用户和前端支撑

### 工作内容

- 用户、角色、权限和登录。
- 看板聚合接口。
- SignalR推送设备状态和实时报警。
- Vue 3前端工程骨架和OpenAPI客户端生成。
- 操作审计。

### 验收场景

- 用户只能看到授权模块和执行授权操作。
- 前端断线重连后主动重新查询当前状态，不依赖丢失的推送补历史。
- 报警产生后前端在目标延迟内收到通知。
- 用户修改配置留下修改前后值、用户和时间。

## 6. M4：生产加固

- 并发、长稳、断网、数据库故障和磁盘满演练。
- 数据备份与恢复演练。
- Windows Service安装、升级和回滚脚本。
- 数据清理、归档和容量监控。
- 安全检查、依赖更新策略和供应商开发手册。

## 7. 非功能目标初稿

以下为首轮目标，需要按设备数量修订：

| 指标 | 初始目标 |
|---|---|
| 心跳/普通事件接收 | P95小于300ms（同局域网、数据库正常） |
| 报警接收 | 高优先级，不被历史补传阻塞 |
| API可用性 | 单机部署目标99.5%，后续按需求升级 |
| 单条消息大小 | 普通消息默认不超过256KB |
| 查询分页 | 默认50，最大500 |
| 幂等 | 任意重试次数只产生一条业务记录 |
| 时间精度 | 数据库保留微秒字段，业务按实际采样能力使用 |
| 断网缓存 | 默认7天，可配置且有磁盘告警 |
| 日志敏感信息 | 密码、令牌、连接串不得输出 |

## 8. 第一周建议安排

### 第1天

- 评审本文档、确认系统边界和第一批消息。
- 确定编码规范和数据库命名。

### 第2天

- 创建解决方案和项目结构。
- 完成配置、日志、异常、OpenAPI、健康检查。

### 第3天

- 建立MySQL迁移机制和基础表。
- 完成设备主数据与凭据模型。

### 第4天

- 完成心跳接入、幂等和设备状态。
- 编写集成测试和模拟客户端。

### 第5天

- 将一台HTHIUM接入正式心跳接口。
- 测试断开、恢复、重复发送和非法凭据。
- 输出第一阶段验证报告。

## 9. 正式编码前的评审出口

满足以下条件后开始M0代码实施：

- 系统边界没有争议。
- 确认使用独立MES数据库。
- 确认.NET 10、MySQL、SqlSugar和模块化单体路线。
- 确认第一批接入消息及其字段来源。
- 确认设备、产线、站点编码规则负责人。
- 确认开发、测试、生产配置不得混用。
